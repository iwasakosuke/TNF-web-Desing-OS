# Client_Intake_Flow

案件の入口。クライアントからの問い合わせを、Project_Start_Flowが着手できる
「確定ブリーフ」に変換するまでの手順。

## 目的

情報不足のまま制作に着手し、後工程（Design_Production_Flow）で手戻りが発生することを
防ぐ。ヒアリング漏れは、洗練度以前に「そもそも作り直しになる」最大の原因であるため、
この段階の徹底が全工程のスピードを決める。

## フェーズ

### Phase 1: 一次受付
- **担当**: CEO_AI（窓口）
- **入力**: クライアントからの問い合わせ内容（自由記述）
- **やること**: 案件の種別（LP/コーポレート/サービスサイト/SNS/提案資料/バナー）を
  特定し、08_PROJECT_TEMPLATES配下の該当カテゴリと紐付ける
- **出力**: 案件種別の一次判定 + Brand_Strategist_AIへの引き継ぎメモ
- **完了条件**: 案件種別が1つに定まっている

### Phase 2: ヒアリング
- **担当**: Brand_Strategist_AI
- **入力**: 一次判定結果
- **やること**: 下記「必須ヒアリング項目」を漏れなく収集する
- **出力**: ヒアリングシート（下記フォーマット）
- **完了条件**: 必須項目がすべて埋まっている、または「未確定」として明示されている

### Phase 3: ブリーフ確定
- **担当**: Brand_Strategist_AI → Master_Creative_Director_AI承認
- **入力**: ヒアリングシート
- **やること**: ヒアリング内容を「Client Brief」形式に整理し、
  Master_Creative_Director_AIの承認を得る
- **出力**: Client Brief（Project_Start_Flowへの正式な引き継ぎ資料）
- **完了条件**: Master_Creative_Director_AIの承認が下りている

## 必須ヒアリング項目

```markdown
## Client Brief

### 基本情報
- クライアント名 / 業種
- 案件種別: LP / コーポレートサイト / サービスサイト / SNS / 提案資料 / バナー
- 希望納期
- 予算感（あれば）

### 目的
- このアウトプットで達成したいこと（1つに絞る。複数ある場合は優先順位）
- ターゲットユーザー像

### ブランド情報
- 既存ブランド資産の有無（ロゴ・カラー・フォント・過去の制作物）
- 参照したい競合・憧れのブランド（あれば）
- トーン希望（フォーマル/カジュアル/ラグジュアリー等）
- 絶対にやりたくない表現（NGイメージ）

### 素材・データ
- 提供可能な写真・コピー・実績データの有無
- 公開後の運用者（自社更新か、継続依頼か）

### 未確定事項
- [ヒアリング時点で決まっていない項目をここに列挙し、Project_Start_Flowで
  再確認する対象として明示する]
```

## 完了条件（このFlow全体）

- Client Briefがすべての必須項目について「回答」または「未確定」の明示を持っている
- 案件種別が08_PROJECT_TEMPLATESのいずれかのカテゴリに対応している
- Master_Creative_Director_AIの承認印（レビューコメント）が付いている

## 次フェーズへの引き継ぎ

- Client BriefをそのままProject_Start_Flowの入力として渡す
- 「未確定事項」がある場合は、Project_Start_Flowのキックオフで
  優先的に解消する項目として申し送りする

## NG例

```
クライアントから「かっこいいLPを作ってほしい」とだけ受け取り、
目的・ターゲット・予算・納期を確認しないままDesign_Production_Flowに着手する。
```
必須ヒアリング項目が欠落したまま次工程に進むと、後工程すべてが手戻りリスクを負う。

## 良い例

```
ヒアリング時点で「ターゲットユーザー像」が未確定だったため、
Client Briefの「未確定事項」に明記した上でブリーフを確定。
Project_Start_Flowのキックオフミーティングで最優先事項として扱う。
```
不明点を隠さず可視化することで、後工程が計画的にリスクを吸収できる。
