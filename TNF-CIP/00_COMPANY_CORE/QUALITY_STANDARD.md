# QUALITY_STANDARD

TNF-CIPが納品するすべての成果物が満たすべき、測定可能な品質基準。
DESIGN_CONSTITUTION.mdが「思想・判断基準」を定めるのに対し、本ファイルは
「合否をどう判定するか」という検査基準そのものを定義する。QA_Divisionと
Design_Reviewer_AIは、本ファイルを一次チェックリストとして使用する。

## ミッション

「なんとなく良い/悪い」という主観判定を組織から排除し、Apple／Linear／Stripe／
Framer／Aesop／Blue Bottle Coffee水準の品質を、誰が採点しても同じ結果になる
客観基準として運用可能にすること。品質は「センスの有無」ではなく「基準への準拠度」で
管理されるべきだという前提をTNF-CIP全体に徹底する。

## 実務での役割

- QA_Divisionは、すべての納品物に対して本ファイルのチェックリストを機械的に適用する
- Design_Reviewer_AIは、指摘を出す際に必ず本ファイルの該当項目番号を引用する
- Master_Creative_Director_AIは、本ファイルの基準を満たさない成果物の出荷を拒否する
  最終権限を持つ
- 各Division・各AI社員は、着手前に本ファイルを読み、後工程で指摘を受けにくい
  初速の高い制作を行う

## 判断基準

品質は以下4層の合格ラインで判定する。下位層が崩れている場合、上位層がどれだけ
優れていても全体は不合格とする。

1. **構造層**: グリッド整合性・情報階層・レスポンシブ耐性（崩れたら即NG）
2. **表現層**: 配色・タイポグラフィ・写真・余白のプロ水準への到達度
3. **体験層**: モーション・インタラクション・読み込み体験の自然さ
4. **語調層**: コピーのトーン、ブランドの一貫性、誇張表現の有無

## 入力フォーマット

```
- レビュー対象（URL、コード、Figmaリンク等）
- 参照ブランドDNA（03_STYLE_DNA / 04_VISUAL_DNA）
- 対象デバイス・ブレークポイント
- 案件のQuality Standard特例（あれば。例: 予算都合で写真は既存素材流用 等）
```

## 出力フォーマット

```markdown
## QUALITY_STANDARD 判定結果

### 総合判定: 合格 / 条件付き合格 / 不合格

### 構造層
- [ ] グリッド整合性: 基準単位(4px/8px)の倍数のみで構成されているか
- [ ] 情報階層: 視線誘導が意図通りか（Heroから最終CTAまで一直線か）
- [ ] レスポンシブ: 375/768/1440で崩れがないか

### 表現層
- [ ] 配色: 有彩アクセントカラーは2色以内か
- [ ] タイポグラフィ: フォントは3種類以内、スケールが比率で統一されているか
- [ ] 写真: 光・構図・トーンに一貫性があるか、ストックフォト感がないか
- [ ] 余白: セクション間に十分な呼吸があるか（詰め込みすぎていないか）

### 体験層
- [ ] モーション: すべての動きに目的があるか、200-400msの範囲か
- [ ] インタラクション: ホバー/クリックの反応が即時か
- [ ] 読み込み体験: 主要コンテンツの表示が遅延していないか

### 語調層
- [ ] コピーがブランドDNAのトーンと一致しているか
- [ ] 誇張・最上級表現の乱用がないか

### 指摘事項（不合格・条件付き合格の場合）
1. [項目名]: [具体的な問題] → [修正指示]
```

## 品質基準

- 構造層は100%準拠が必須（1つでも崩れがあれば即不合格）
- 表現層・体験層・語調層はそれぞれ80%以上の準拠率で「条件付き合格」、
  全項目準拠で「合格」とする
- 「条件付き合格」の場合も、未達成項目は次回納品までに解消することを条件とする
- 主観的な形容詞（「なんとなく」「もう少し」）のみの指摘は無効とし、
  必ず本ファイルの項目に紐づけて再指摘させる

## NG例

```
判定: 不合格
指摘: 「全体的にちょっと安っぽい気がします」
```
本ファイルのどの項目にも紐づかない主観的な指摘であり、修正のしようがない。
QUALITY_STANDARDの運用としては無効な指摘。

```
判定: 合格（実態は不合格水準）
- グリッド崩れ、フォント4種類混在があるにもかかわらず「見た目は良いので合格」
```
構造層が崩れている時点で表現層の出来に関わらず不合格とすべきところを、
主観的な「見た目の良さ」で構造層の欠陥を覆い隠している誤判定。

## 良い例

```
判定: 条件付き合格
指摘:
1. 表現層/配色: 有彩アクセントカラーが3色（テラコッタ・ブルー・グリーン）使用されており
   基準の2色以内を超過 → CTAのブルーをテラコッタに統一し、グリーンは
   ステータス表示のみに限定すること
2. 体験層/モーション: Heroのフェードインが800msで基準(200-400ms)を超過
   → 400ms・easeOutExpoに調整すること
```
指摘が本ファイルの項目番号・具体的な数値に紐づいており、修正者が迷わず対応できる。

## 他AI社員への引き継ぎ方法

- QA_DivisionのDesign_Reviewer_AIが一次判定を行い、不合格・条件付き合格の場合は
  該当するAI社員（Senior_UI_Designer_AI, Visual_Director_AI, Motion_Designer_AI等）に
  項目単位で差し戻す
- Master_Creative_Director_AIには「総合判定」のみをエスカレーションし、
  詳細な指摘事項は各担当AI社員との間で完結させる（Master判断の負荷を減らす）
- 同一案件で3回以上同じ項目の指摘が繰り返される場合、Style_DNA_Manager_AIに
  「このパターンをDNAライブラリに明示的な禁止事項として追記すべきか」を提起する

## そのまま使えるプロンプト

```
あなたはTNF-CIPのQA_Divisionに所属するレビュアーです。
QUALITY_STANDARD.mdの4層基準(構造層/表現層/体験層/語調層)に基づき、
以下の成果物をApple/Linear/Stripe水準で採点してください。

【入力】
- レビュー対象: [URLまたはコードを貼付]
- 参照ブランドDNA:
- 対象ブレークポイント: 375 / 768 / 1440

【出力条件】
- 構造層は1項目でも未達なら即不合格と判定すること
- すべての指摘は本ファイルの項目名に紐づけ、具体的な数値で修正指示を出すこと
- 「なんとなく」「もう少し」等の主観語のみの指摘は禁止すること

出力は本ファイルの「出力フォーマット」に厳密に従ってください。
```

## レビュー基準

- [ ] 総合判定が「合格/条件付き合格/不合格」の3値で明確に出されているか
- [ ] 構造層の崩れが1つでもあれば不合格と正しく判定されているか
- [ ] すべての指摘が具体的な数値・項目名を伴っているか
- [ ] 主観語のみの指摘が排除されているか
- [ ] 差し戻し先のAI社員が明確に指定されているか
